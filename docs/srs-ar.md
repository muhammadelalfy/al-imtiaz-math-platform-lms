| --------------------- | ------------------------------------------------------------------------------------------------------- |
| اسم النظام            | منصة الامتياز في الرياضيات                                                                              |

> **حالة Stripe:** الدفع بالبطاقة عبر Stripe ليس مفعلاً في هذا الإصدار. لا يبدأ تنفيذه إلا بعد أن يضع مالك المشروع مفاتيح Stripe السرية ومفتاح النشر في **Settings → Payment**. لا تُدخل أي مفاتيح مزود دفع في لوحة إدارة المركز.

## 1. الغرض والسياق

تحدد هذه الوثيقة المتطلبات الوظيفية وغير الوظيفية لمنصة **الامتياز في الرياضيات**، وهي نظام إدارة تعلم عربي لمركز تدريس الرياضيات. يركز النظام على إدارة الطلاب والصفوف، متابعة الحضور الذكي، إعداد الاختبارات والشيتات، مراقبة جلسات الاختبار ضمن حدود المتصفح، عرض النتائج والتقارير، وإتاحة إضافات وظيفية من خلال متجر داخلي. التطبيق الحالي مبني كتطبيق Laravel 13 مع واجهة React 19 مدمجة عبر Inertia، ويستخدم Eloquent وواجهات API محمية بحسب الدور [1].

تعتمد الوثيقة على ما هو مطبق فعلياً، ولا تعرض أي بند مستقبلي على أنه متاح. ينفذ الإصدار الأول من العمل دون اتصال فقط لسجلات الحضور والنتائج والمدفوعات وتسليمات الشيتات، بينما تبقى Stripe والنسخ الكامل للمحتوى خارج هذا النطاق.

## 2. النطاق

يشمل نطاق المنتج إدارة دورة التعلم في مركز الرياضيات من إنشاء الطالب وتهيئة صفه، مروراً بالحضور والشيتات والاختبارات، وانتهاءً بعرض النتائج والمؤشرات. كما يشمل متجر الإضافات وآلية الدفع اليدوي المراجَع إدارياً.

| داخل النطاق الحالي                                                                | خارج النطاق الحالي أو مؤجل                                      |
| --------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| إدارة الطلاب والصفوف والمجموعات وبطاقات الطلاب                                    | تطبيق جوال أصلي مستقل                                           |
| دخول منفصل للإدارة والمعلم والطالب وولي الأمر، مع إدارة أدوار وصلاحيات العاملين   | تشغيل كامل بلا شبكة أو نسخ كامل لمحتوى المنصة                   |
| QR شخصي للطالب، مسح الحضور، وتسجيل التاريخ والوقت والحالة                         | ربط مباشر مع واجهات Vodafone Cash أو InstaPay أو Fawry التجارية |
| شيتات وتعيينات وتسليمات، واختبارات وقوالب وبنك أسئلة                              | Stripe Checkout وWebhook قبل إعداد مفاتيح المالك                |
| محرر نص غني، معادلات، صور، وأسئلة هندسية بأبعاد                                   | تصحيح آلي قائم على الذكاء الاصطناعي                             |
| تقارير ملخصة للطلاب والحضور والاختبارات والمدفوعات                                | نظام رسائل أو إشعارات متعدد القنوات                             |
| متجر إضافات، تثبيت وحدات، ومدفوعات يدوية مدققة                                    | نظام اشتراكات دورية أو كوبونات Stripe                           |
| مزامنة محددة للسجلات عبر لقطة آمنة وطابور IndexedDB وإعادة تشغيل متوافقة مع الدور | تعديل سجلات حساس أو إعدادات أو إضافات أثناء عدم الاتصال         |

## 3. أصحاب المصلحة والمستخدمون

يعتمد النظام أربعة أدوار تشغيلية. لا يحدد إخفاء عنصر من الواجهة الصلاحية وحده؛ بل تطبق الواجهات البرمجية كذلك تحققاً قائماً على الدور وطلبات تحقق مخصصة قبل تنفيذ عمليات الكتابة [2].

| الدور       | المسؤولية الأساسية                               | أمثلة على القدرات                                                                                                                     |
| ----------- | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| مدير المركز | الإدارة والاعتماد والرقابة                       | إدارة الطلاب والصفوف والمدفوعات، إعداد طرق الدفع، مراجعة مراجع التحويل، تثبيت الإضافات، إسناد الأدوار المخصصة للعاملين، وعرض التقارير |
| المعلم      | إعداد المحتوى والمتابعة الأكاديمية ضمن الصلاحيات | بناء الأسئلة والاختبارات والشيتات، متابعة الحضور والنتائج المسموح بها، وإدارة الأدوار والصلاحيات المخصصة عند إسناد إذن نظامي له       |
| ولي الأمر   | المتابعة المقيدة للطالب المرتبط به               | الاطلاع على الحضور والنتائج والشيتات والحالة المالية المصرح بها                                                                       |
| الطالب      | أداء الواجبات والاختبارات والمتابعة الذاتية      | عرض QR الشخصي، فتح الشيتات، تقديم الحلول، أداء الاختبارات المنشورة، الاطلاع على النتائج                                               |

## 5. مخطط أدوار الوصول

_يعرض الرسم التالي الفصل بين الأدوار وطبقات القدرات التشغيلية. يؤكد الرسم أن مراجعة المدفوعات وإعداد تعليمات الدفع من صلاحيات مدير المركز فقط._

## 6. مخطط سير العمل التعليمي

_يوضح الرسم دورة العمل من إدارة الطلاب والحضور، إلى الاختبارات والشيتات، ثم النتائج ولوحة المؤشرات._

![مخطط سير العمل التعليمي في منصة الامتياز في الرياضيات](/manus-storage/lms-workflows_306cd262.png)

## 7. مخطط دورة دفع الإضافات

_يوضح الرسم الحالة اليدوية المنفذة حالياً، والفاصل المقصود لـ Stripe إلى حين تقديم مفاتيح المالك. لا تُمنح صلاحية التثبيت قبل اعتماد المدير أو تحقق webhook الموقّع في مسار Stripe المستقبلي._

![مخطط دورة دفع الإضافات والاستحقاق](/manus-storage/plugin-payment_191d3eb1.png)

## 8. مخطط المعمارية والمنعزل المستقبلي لـ Stripe

_يظهر الرسم الواجهة العربية، وطبقات API والتحقق والمستودعات والتخزين المؤقت وقاعدة البيانات والوحدات. أظهر فحص الرسمين المعماري ودفع الإضافات أن حدود Stripe موضوعة بخط متقطع وموسومة بأنها مشروطة بإضافة مفاتيح المالك، بينما مسار الدفع اليدوي يتجه حصراً إلى مراجعة المدير والاستحقاق الذري._

## 12. الاختبارات وضمان الجودة

تطبق المنصة بوابة جودة قبل حفظ كل ميزة: اختبارات Laravel، التحليل الساكن Larastan، فحص TypeScript، اختبارات Vitest، lint، بناء Vite للإنتاج، تحقق Composer، تنسيق وثائق وCI، وفحص فراغات التغييرات. اجتازت إضافة طرق الدفع اليدوية هذه البوابة بـ **225 assertion** في اختبارات Laravel ومن دون أخطاء Larastan [3].

### 15.1 الحدود الأمنية والتشغيلية

تستخدم إدارة الباقات والاشتراكات مستودعات Eloquent ضيقة وخدمات تطبيقية؛ تبقى عمليات إنشاء مركز/معلم وتحديث الاشتراك داخل معاملات قاعدة بيانات مع إعادة محاولة محدودة، وتحول أخطاء التخزين إلى رسائل عربية آمنة. يقتصر تفعيل النطاق على المشرف الأعلى، ولا يتعامل التطبيق مع شراء النطاقات أو شهادة TLS أو سجلات DNS نيابة عن المالك. ينفذ تذكير الأسبوع قبل الانتهاء عند تسجيل الدخول وفق الخيار **B** المختار، ولا يعتمد على مؤقت داخل العملية أو تنفيذ مجدول.

### 15.2 التتبع والجودة

يضاف كل مطلب جديد في هذه الوثيقة مع اختبار API أو واجهة مناسب قبل إغلاقه. تمر حزمة الإصدار على اختبارات Laravel، التحليل الساكن Larastan، تحقق Composer، اختبارات TypeScript/Vitest، بناء Vite، والتحقق من المسافات؛ ثم تراجع فحوص GitHub Actions للفرع المنشور قبل دمج أي تغيير.
